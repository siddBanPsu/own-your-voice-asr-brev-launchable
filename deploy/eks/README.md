# Deploy the customized Riva ASR NIM on Amazon EKS

This is the production-oriented Lab 3 path. It assumes an existing EKS cluster
with homogeneous NVIDIA GPU nodes, `kubectl`, Helm, an S3 bucket, and NGC
entitlement. Cluster creation is intentionally outside the attendee lab because
it changes AWS infrastructure and usually takes longer than the model exercise.

The deployable input is `artifacts/riva/own_your_voice_asr.rmir`, generated by
`scripts/build_riva_rmir.sh`. The RMIR is hardware-independent. The Speech NIM
Helm chart downloads it from S3, runs `riva-deploy` on the target GPU, creates
the optimized Triton repository, and exposes the Riva HTTP and gRPC APIs.

Riva SDK 2.26 does not publish an x86 `riva-speech:2.26.0` image. NVIDIA directs
x86 data-center users to Speech NIM, so this guide uses the `riva-nim` chart and
the published Parakeet 0.6B ASR NIM image.

## 1. Validate the EKS GPU boundary

```bash
aws sts get-caller-identity
kubectl cluster-info
kubectl get nodes -o=custom-columns=NAME:.metadata.name,GPU:.status.allocatable.nvidia\.com/gpu,GPU_PRODUCT:.metadata.labels.nvidia\.com/gpu\.product
```

The cluster must expose `nvidia.com/gpu` and have the NVIDIA GPU Operator or the
cluster's supported NVIDIA device mechanism configured. Do not install competing
device-management mechanisms on the same nodes.

## 2. Upload the RMIR to S3

```bash
export AWS_REGION='<cluster-region>'
export RMIR_S3_URI='s3://<bucket>/rmir/own_your_voice_asr.rmir'
aws s3 cp artifacts/riva/own_your_voice_asr.rmir "${RMIR_S3_URI}"
```

Grant the deployment read-only access to that object. Prefer EKS Pod Identity or
IRSA over static AWS keys. If the chart expects a Kubernetes secret, configure
its `awsCredentials.secretReadOnlyName` field after inspecting the chart values.

## 3. Fetch the Speech NIM chart and create NGC secrets

```bash
export RIVA_NIM_CHART_VERSION=1.1.0
export NGC_API_KEY='<personal NGC key>'
helm fetch "https://helm.ngc.nvidia.com/nim/nvidia/charts/riva-nim-${RIVA_NIM_CHART_VERSION}.tgz" \
  --username='$oauthtoken' --password="${NGC_API_KEY}"

kubectl create namespace riva --dry-run=client -o yaml | kubectl apply -f -
kubectl -n riva create secret docker-registry ngc-secret \
  --docker-server=nvcr.io --docker-username='$oauthtoken' \
  --docker-password="${NGC_API_KEY}"
kubectl -n riva create secret generic ngc-api \
  --from-literal=NGC_API_KEY="${NGC_API_KEY}"
```

Do not commit the API key, AWS credentials, or a rendered Kubernetes Secret.

## 4. Configure the custom RMIR

Copy `deploy/eks/values-custom-rmir.yaml` to a temporary file and replace:

```yaml
- s3://REPLACE_ME/rmir/own_your_voice_asr.rmir
```

with the exact `RMIR_S3_URI`. Inspect the fetched chart before installation:

```bash
helm show readme "riva-nim-${RIVA_NIM_CHART_VERSION}.tgz"
helm show values "riva-nim-${RIVA_NIM_CHART_VERSION}.tgz"
```

Fill in the chart's `awsCredentials` section or bind an EKS service account with
read-only S3 access. The image tag and chart version are pinned independently:
the Riva client API version does not select the server image.

## 5. Install and verify

```bash
helm upgrade --install riva-nim "riva-nim-${RIVA_NIM_CHART_VERSION}.tgz" \
  --namespace riva \
  --values /tmp/own-your-voice-riva-values.yaml

kubectl get pods,svc -n riva -w
kubectl logs -n riva -l app.kubernetes.io/instance=riva-nim --tail=100
kubectl port-forward -n riva service/riva-nim 50051:50051 9000:9000
```

In another terminal, verify `curl -fsS http://127.0.0.1:9000/v1/health/ready`,
then run the same Riva Python client cell from Lab 3 against
`127.0.0.1:50051`.

For external production traffic, use an ingress or load balancer that supports
HTTP/2 and gRPC, add TLS, health checks, metrics, authorization, and
workload-based autoscaling. Do not expose Triton's internal ports as the public
application contract. Optimized repositories are GPU-specific, so keep nodes
homogeneous when reusing a model cache and load-test the actual EKS GPU type.
